# crush.lu one-time review — 2026-10-05

> **DELETE AFTER TRIAGE.** This file exists only to carry the review of crush.lu (`crush_lu` app) done on 2026-10-05 against `main` @ `ec37261`. It is not part of the product and should be removed once the findings have been triaged (the content also lives in the linked issues and fix PRs).

Method: 11 read-only reviewers (correctness ×2, security ×2, money, UX ×2, i18n, performance, maintainability, product) → 156 raw findings → merged into 60 verification groups (88 finding ids) → each group handed to an independent verifier whose job was to **disprove** it, writing a failing test or repro where feasible → 5 isolated fixers for the S-effort, low-risk, non-overlapping confirmed bugs → this report. Only this repository was available: no production access, no Postgres, no real devices, no browser run. Every concurrency/locking claim is reasoned from code and **untested on Postgres** (SQLite ignores `select_for_update`).

## 1. Executive summary — top 10

Severities below are the **verified** ones (verifiers downgraded 32 of the 88 verified ids after tracing mitigations: 7 of the 9 reviewer-rated P1s went to P2 and 25 P2s to P3; none went up; the original rating is shown in the table).

1. **P1** — **OAuth landing logs anyone in with a leaked/guessed `state` id** (`views_oauth_popup.py:215-243`). No expiry, binding or single-use check, the `user_logged_in` signal re-arms the row on every redeem, and nothing ever purges `OAuthState`. Because `db_unstash_state` falls back to the DB when the session lacks the state, a login-CSRF variant needs no log access. · Issue [#1182](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1182)
2. **P1** — **"Delete entire account" is not erasure.** Only the `CrushProfile`-keyed rows go; ~30 `User`-keyed tables (Connect chats, answers, coffee dates, push endpoints, device installs, notifications, OTP phone numbers, blocks/reports…) survive because the `User` row is anonymised, never deleted (`views_account.py:472-643`). · Issue [#1183](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1183)
3. **P2** — **Marketing email ignores consent.** `resolve_audience()` never checks `crushlu_consent_given` (never-consented lazily-created profiles are mailed) and nothing reads `marketing_consent`/`email_marketing`; the "Marketing & Promotions" toggle in settings has no effect and there is no newsletter opt-out UI. · Issue [#1184](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1184) · Issue [#1185](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1185)
4. **P2** — **Check-in trust model:** the CSRF-exempt, unauthenticated check-in URL on the member's own ticket lets a member flip themselves to `attended` from home (±12 h window), which unlocks the live-lobby photo roster and the post-event named attendee list; a coachless self-scan is also recorded as a coach grant, which satisfies the Connect identity gate. · Issue [#1186](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1186) · Issue [#1187](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1187)
5. **P2** — **IP rate limits don't limit.** DRF-style throttles (login, password reset, quiz PIN, signup, phone verification) key on the raw `X-Forwarded-For` string including the per-connection port; rotating the port defeats every one (repro: 12/12 PIN guesses, 10/10 logins). · Issue [#1189](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1189)
6. **P2** — **A rejected member can un-reject themselves** through `save-step1/2/3`, `complete` or `create_profile` (no guard on `verification_status == "rejected"` when there is no `ProfileSubmission` row) and then self-verify through LuxID. · Issue [#1188](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1188)
7. **P2** — **Event-payment dead ends:** a captured payment whose price/seat changed is left `PAID` with no credit, no case, a "success" page and a second-charge path; an ambiguous SumUp timeout locks the registration out of paying and the cleanup command deliberately never releases it. (Premium equivalents are already tracked in #925/#1163.) · Issue [#1191](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1191) · Issue [#1190](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1190)
8. **P2** — **GDPR gaps beyond deletion:** the ban/consent middleware exempts `/api/`, `/media/`, `/oauth/` so a "deleted" or non-consenting member can keep writing data, and the data export omits phone, location, preferences and emits non-existent fields. · Issue [#1193](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1193) · Issue [#1194](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1194)
9. **P2** — **Safety:** event grouping, curated pairings and quiz rotation ignore `UserBlock`, so a member who blocked someone can be seated with them. · Issue [#1195](https://github.com/EuphoriaLux/Multi-Domain-Django-Platform/issues/1195)
10. **P2** — **DE/FR members get English in mandatory flows.** 34 gettext strings used by JS are missing from `djangojs.po` (phone verification, voting; verified by serving `/jsi18n/de|fr/`); phone-verification, block/report and credit/cancellation server messages are fuzzy or untranslated in DE/FR; and informal FR address is more widespread than the figures in AGENTS.md (30) and #1166 (9): the verifier re-measured 34 strict `tu/ton/tes/toi` entries and 60 including `te/ta/t'`. The reviewer also counted ~236 untranslated + ~260 fuzzy msgstrs per language and 515 source msgids absent from `django.po`; those two numbers were **not** independently re-measured. Details in the i18n entries below; all of them need `.po` edits and should be one PR after #1163 and #1175 merge. 

**Also shipped as draft PRs (10 finding ids fixed, tests failing-before / passing-after):** private-invitation event gating (anonymous 500 + calendar leak), quiz REST roster IDOR, Crush Credit restore on a spendable expiry, credential hygiene (Facebook token in logs, non-ASCII `compare_digest` 500s), and two member-page leaks (unsubscribe page impersonating its token owner, raw gift-claim exception text). See §3.

**Suite health:** the full default suite (`pytest`, Playwright excluded) finished with 7,988 passed, 435 subtest-passes, 38 skipped, **0 failures / 0 errors** (8,461 progress marks; no flaky test observed). The review is therefore about gaps the suite does not exercise, not regressions.
